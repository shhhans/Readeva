# 测试

## 测试边界

按父规格 Testing Decisions：**浏览器完整操作流程为主要测试边界**；日常自动化使用固定数据，不依赖外部服务；外部能力（Docling）通过固定结果和真实接入两层验证。

端到端测试使用 Playwright（Chromium 无头模式，Windows 本机可运行），测试自行以**生产同一入口**（`server/index.js`，临时数据目录）启动独立服务进程，并在用例中真实重启服务。日常自动化的 Docling 依赖由 `tests/helpers/mock-docling.js` 提供：实现 docling-serve 兼容线协议（异步提交/状态轮询/结果获取）的 HTTP mock，返回固定 DoclingDocument JSON（`tests/fixtures/docling/`），验证对外行为及保存成果，不依赖真实外部服务。

### 按阅读位置的解析调度（Issue #5）

服务接口测试 `tests/e2e/parse-scheduler.spec.js`（串行；每用例独立服务进程与 mock，队列内存态隔离后顺序断言才确定；`READEVA_PARSE_CONCURRENCY=1` + 高轮询频率保证确定性）：

| # | 验收标准 | 用例与关键断言 |
| --- | --- | --- |
| 1 | 当前页及后续页优先 | 「阅读位置更新：当前页立即解析，后续页优先排队，前置页降级」：`PUT reading-position {page:3}` 后第 3 页 running、4-8 按 queuePosition 0-4 排队、1-2 降级到队尾（仍 queued，闲置补全覆盖）；mock 实际提交顺序为 page-3 → page-4 → page-5，前置页尚未开始 |
| 2 | 跳页后更新未开始任务优先级 | 「跳页后重排未开始任务」：第 2 页运行中跳到第 6 页 → 队列重排为 [6,7,8,1,3,4,5]（运行中页不取消不重复入队），转换提交顺序 page-2 → 6 → 7 → 8 → 1 → 3 → 4 → 5 |
| 3 | 闲置时解析其他未解析页；已完成结果直接复用 | 「闲置补全」：上报阅读位置后无需其他请求，整本 8 页全部 succeeded（每页有 parseId）；已完成页 POST 解析 → `reused:true` 且转换请求数不变 |
| 4 | 失败页可显式重试，其他页面继续处理 | 「失败页不阻塞队列」（mock 按页失败注入 page-4）：其余 7 页全部完成，失败页状态 failed 带原因、结果 404、不自动重试；「失败页显式重试」：解除注入后 POST 重试 → 202 running → succeeded，仅新增 1 次转换，其他页结果不受影响 |
| 5 | 服务接口测试覆盖 | 以上用例全部走服务 HTTP 接口（import/reading-position/parse/status/progress/result），断言基于 mock 记录的真实提交顺序 |

补充用例：「显式解析请求优先于队列」（并发占满时 202 queued 且置于队首，完成后先解析显式页）；「显式请求置顶不被随后的阅读位置重排降级（pinned）」（置顶页重排后仍在队首：队列 [5,8,2,3,4,6,7]，提交顺序 page-1 → 5 → 8 → 2 → …）；**并发调度**：「并发 2：两页同时转换」（PUT 响应快照即见 p1/p2 双 running、其余排队，扫全后每页恰好一次转换，兼验开局双槽同步填充）、「并发 2 跳页插队」（置顶页先于阅读顺序 3/4/5/7/8，staggered 不预留空槽）、「并发上限钳制」（0/非法值回落 1、配置 3 → 三页同时 running）、「扫全节流」（固定间隔覆盖动态 pacing：开局填充后生效，显式请求不受限）、「动态 pacing：背景派发间隔随最近转换耗时缩放」（慢页相 p3→p4 间隔 > 150ms，setConvertDelay 切快页后收敛至慢相的一半以下——阈值为相对倍数，CI 负载下不飘；两相开局均双槽同步）；**pacing 按文档分桶**（固定 800ms 间隔 + 快页 + 并发 2：B 的首页先于 A 的第一个被间隔约束的背景页派发、B 的背景页间隔 ≈ B 自己的 800ms——A 的间隔不挡 B）、**当前页豁免 pacing**（固定 1200ms 间隔 + 跳页：当前页在下一槽释放时立即派发，间隔 < 900ms，不被 1200ms 背景间隔拖住）、**不节流档**（`READEVA_PARSE_SWEEP_PACING_FACTOR=0`：并发 2 下第 3→4 次提交间隔 < 150ms，无 pacing 等待）；「单页解析请求不触发整本调度」（Issue #3 行为保持）；「进度快照基于持久化记录：重启服务后进度不丢、已完成页不重新解析」；「阅读位置与进度接口的参数校验与降级」（非法页 400、未知文档 404）；「未配置解析服务：阅读位置更新降级不调度，进度接口仍可用」。

B1 规模回归：「B1 规模回归：进度/重排接口走轻量状态索引，不逐轮全量读盘」——导入 210 页 PDF，直接落盘 210 条 ~600KB 成功记录（含 base64 图片资源，等价真实单页记录体积）；首次调用建立轻量状态索引后，连续 3 次 `GET /parse/progress` 与 1 次 `PUT reading-position` 各自耗时 < 250ms（退回全量读盘会退化到数百 ms/轮，审核官实测 ~0.3s/139MB），且不触发任何新增解析。

浏览器级用例 `tests/e2e/parse-inline-status.spec.js`（mock Docling，Issue #5 收敛轮后的验收契约）：**单页解析状态内联在内容列表**（状态徽标 + 「第 N 页」说明，进行中/排队中带状态标记；失败条目带「解析失败」徽标 + 失败原因 + 显式重试按钮，就地重试后恢复）；**整体进度为面板头部一处静态文本**（如「解析 12/215 · 失败 1」，失败只计数不列页码）——事件（派发/完成/失败/重试/翻页）时取一次快照更新，阅读视图打开期间另以固定 8s 间隔慢刷新（离开阅读视图即停止，无每秒轮询）：用例断言空闲 3s 内无整本进度请求、12s 内恰一次慢刷新且间隔落在 5–10s、返回书库后不再出现整本进度请求；**独立进度区彻底移除**（无 `#parse-progress` 容器、无逐页页码芯片）；闲置补全后台完成且整本每页恰好一次转换（转换请求数不变），已完成页直接复用不重新解析；「事件驱动自愈」——删除已解析页落盘记录模拟「队列丢失 + 记录缺失」状态后，面板自动重报阅读位置，该页重新入队解析并回到 8/8。

既有浏览器用例适配（调度交付后的行为变化，意图不变）：`parse-panel.spec.js` 的「跳页到第 3 页」改为断言 page-3.pdf 确实被请求（整本调度会补全其他页，提交顺序断言移至 parse-scheduler.spec.js）；「回到已解析页与重开文档」先等待后台补全完成再断言复用；「解析失败状态与原因可见，重试后恢复」改用未解析的 sample-b（行为脚本第 1 次成功、其后失败）。收敛轮内，原「面板状态徽标/错误区/独立重试按钮」断言统一改为内容列表内联状态条目断言（`#parse-state .parse-entry[data-page-status=…]` + `.parse-entry-badge` + `.parse-entry-retry`），`linkage.spec.js` 的「悬浮静默」断言同步改为内联状态条目语义。

## 客户端退出与重连恢复（Issue #6）

服务接口测试 `tests/e2e/client-session.spec.js`（串行；每用例独立服务进程与 mock；小宽限期 `READEVA_CLIENT_GRACE_MS` + 串行并发保证确定性；**到期处置只观察只读 session 端点，进度轮询会刷新 lastSeen 从而取消到期**）：

| # | 验收标准 | 用例与关键断言 |
| --- | --- | --- |
| 1 | 浏览器关闭后独立本地服务继续运行 | 「验收 1」：最后一次客户端请求（`PUT reading-position`）后不再发送任何请求，mock 记录服务自主派发完全部 8 页并落盘（默认宽限期 5 分钟在用例时长内不触发） |
| 2 | 宽限期到期：完成已开始页并持久保存，清除尚未开始的任务 | 「验收 2」：宽限期 800ms + 拉长转换（约 1s/页）→ 到期后运行中的第 1 页继续跑完（结果可取回、parseId 合法），2-8 被清除（idle、永不派发、`convertCalls==1`）；**幂等**：再次越过宽限期后已完成保留、清除保持清除、零新增派发、已完成页 POST 仍 `reused:true` |
| 3 | 宽限时间可配置；短暂断线按宽限规则处理 | 「验收 3」：宽限期 3000ms 内「断线」间隙队列照常推进（`convertCalls` 增至 2）且会话未过期；宽限内回来重新上报 → 队列不受影响直接继续，整本 8/8、每页恰好一次转换 |
| 4 | 重连取回已完成成果，并按当前阅读位置重新调度未完成页 | 「验收 4」：到期清除后重连（上报阅读位置到第 3 页）→ 已完成第 1 页复用（parseId/blocks 前后一致、零新增转换），未完成页按「当前页 → 后续页 → 前置页」重新调度（提交顺序 `page-1 → 3 → 4 → … → 8 → 2`），整本 8/8 |
| 5 | 使用可控解析响应验证退出/失联/宽限/排队清除/运行中页完成及重连恢复 | 全部用例基于 mock 可控延迟（`convertDelayMs`）与真实提交顺序断言；浏览器级端到端（`client-session-browser.spec.js`）：真实浏览器打开文档 → `page.close()` 关闭浏览器页面 → 服务继续运行（运行中页跨 1.5s 宽限期完成落盘）→ 宽限期到期清除未开始任务（零新增派发）→ 新页面重连取回成果（parseId 不变）并按阅读位置重新调度，全程 4 页各一次转换 |

补充用例：
- 「默认宽限期 300000ms」：不配置 `READEVA_CLIENT_GRACE_MS` 时 session 端点报告 5 分钟默认值且不误判到期（隐藏标签节流取舍：页面内定时器节流约 1 次/分钟，默认 5 分钟 ≈ 5 个节流心跳余量；既有会话用例全部显式配置短宽限期，不受影响）。
- 「会话端点只读观察」：`GET /api/documents/:id/session` 返回 `{ lastSeen, graceMs, expired }`，宽限期可配置（graceMs=1000），**观察期持续轮询 session 不刷新 lastSeen、到期照常发生**；未知文档 404；未配置解析服务时 `{ supported:false }` 降级。
- **跨文档取任务轮转**：「round-robin 并发 1」两文档（8 页 + 4 页）严格交替派发（`A1,B1,A2,B2,…,B4,A5…A8`，按单页字节 sha256 映射断言）；「round-robin 并发 2」A 未排空前 B 已开始（`B1` 先于 `A8`），12 页各一次转换。
- **状态索引**：解析落盘写 `index.json`（条目含页文件 mtime/size 快照，与页记录一致）；重启后冷启动经索引取状态（进度/parseId 与重启前一致，结果接口完整）；**失效回退**：外部删除页记录 → 状态回到未开始（索引不覆盖文件存在性）；外部替换页记录 → 状态反映新内容（索引防过期）。

## 真实 Docling 接入验证

非自动化层，验收时以真实服务执行（脚本已入库：仓库根目录运行 `node scripts/verify-real-docling.mjs`，结果记录见 PR 描述）。脚本退出清理自证（Windows）：启动即以 `READEVA_VERIFY_PYTHON`（默认环境内 python.exe，绕过 conda 包装层）直连 docling，成功与异常退出路径均用 `taskkill /PID <pid> /T /F` 杀整棵进程树、等待子进程 exit（8s 超时）并探测 5001/8899 健康端口已不可达，防止 uvicorn 孙进程（~2GB）残留；端口仍可达时打警告（可能是外部遗留进程）：

1. 启动解析服务：`conda run -n readeva python -m uvicorn docling_service.main:app --host 127.0.0.1 --port 5001`（conda 环境 `readeva`，docling 2.153.0）。
2. 启动 Readeva 服务：`npm start -- --docling-url http://127.0.0.1:5001`。
3. 导入 Hans 指定 PDF「Inflight Service Manual - Chapter 3 Business Service.pdf」（215 页），解析代表页：状态流转成功；标题/段落/列表/表格/图片资源按阅读顺序返回（第 15 页含全部五类内容块）；全部块带可用位置。
4. 重启 Readeva 服务：已完成页状态/parseId/完成时间不变，解析服务零新增转换请求（不重新解析）。
5. 浏览器打开阅读视图：右侧面板展示真实解析内容（截图留档 `.tmp/real-docling-panel.png`）。

解析输出质量（内容准确性）由解析项目负责，本项目只验证结果消费、展示与保存恢复。
