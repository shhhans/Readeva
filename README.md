# Readeva

PDF 阅读工作台。当前交付 **Issue #8「选文及内容块翻译、保存与复用」**（父规格 [Issue #1](https://github.com/shhhans/Readeva/issues/1)，基于 Issue #2–#7 交付）：

- 书库导入：保存 PDF 副本，以**文件内容 SHA-256 摘要**作为文档身份（文档名不作为身份依据，相同内容不会重复入库）。
- 原页阅读：使用 PDF.js 按原始排版渲染（文字、表格、图片布局与 PDF 原样一致），支持翻页、页码跳转、缩放。
- 页解析：当前页通过独立 Docling 解析服务解析，原页立即打开不等解析；右侧面板按阅读顺序展示标题、段落、列表、表格与图片资源；解析状态可见（未开始/排队/已开始/成功/失败）；解析以页为单位持久保存，重新打开直接恢复不重新解析。
- **客户端会话与宽限期**：任何客户端文档活动（阅读位置上报/进度轮询/状态轮询/解析请求等）都刷新会话最近活跃时间；超过宽限期（`READEVA_CLIENT_GRACE_MS`，默认 5 分钟）无活动即视为客户端退出——**运行中的页继续跑完并持久保存**（不取消），**尚未开始的任务从队列清除**（不派发），处置幂等（重连/多次到期不误伤）；**宽限内回来队列不受影响**，直接继续；**重连**（重新打开文档）取回已完成成果（不重新解析）并按当前阅读位置重新调度未完成页；服务为独立进程，**关闭浏览器不终止服务**（浏览器关闭后队列照常推进）；会话状态可经 `GET /api/documents/:id/session` 只读观察。**默认 5 分钟是为隐藏标签节流留的余量**：浏览器对隐藏标签页的页面内定时器节流（约 1 次/分钟），阅读视图内 8s 慢刷新心跳被稀释后仍不会误判到期（取舍见 README「配置」）。
- **按阅读位置调度**（Issue #5）：打开文档/翻页时上报阅读位置，服务端按「当前页及后续页优先，其余降级」重排未开始任务；跳页只重排未开始任务（运行中页不取消）；显式请求/重试的页置顶，不随翻页降级；队列按序闲置补全整本未解析页；已完成页直接复用；失败页标记原因、不阻塞队列、**不自动重试**，可显式重试；并发上限可配置（默认 2）；背景扫全 pacing 动态自适应设备性能——**pacing 状态按文档分桶**（A 的间隔不挡 B，配合跨文档轮转）、**当前页豁免 pacing**（用户当前页不被背景间隔拖住）、**系数 0 = 不节流档**（关闭动态间隔）；**跨文档取任务轮转**（round-robin，并发下不单个文档排空，新打开/重连的文档优先获得派发轮次）；进度/重排接口走轻量状态索引，且**每文档一份状态索引 `parses/<sha>/index.json`**（保存时增量更新，重启后冷启动免首轮逐页读全量）。
- **单页状态内联在右侧内容列表**（状态徽标 + 失败原因 + 重试按钮），**整体进度只有面板头部一处静态文本**（如「解析 12/215 · 失败 1」）：事件更新 + 阅读期间 8s 慢刷新，失败页只计数不列页码。
- **选词查词（Issue #7）**：在右侧解析原文中选词（双击/拖选），点「查词」主动查询 **ECDICT 离线英汉词典**：结果卡片展示词条、音标、考试标签、中英释义、词性/柯林斯星级/词频/词形变化，页脚展示真实许可与上游数据来源归因；未收录（含超长选文，按未收录 404 反馈）、词典数据未准备、查询失败均有明确反馈。查询是服务端**纯本地文件操作**（构建好的索引 + 词条文件，不访问网络），词典数据准备好后**断网仍可查询**；首版不维护查词历史。词典数据（约 63MB）由 Hans 下载与构建，见下方「词典数据准备」。原文与选文翻译属 Issue #8。
- **选文与内容块翻译（Issue #8）**：右侧主动翻译——选中文本后工具条点「翻译」，或点内容块右上角「翻译」按钮整块翻译（标题/段落/列表/表格；默认目标语言中文）。译文显示在对应内容旁（块后/包含选文的块后），标注来源（内容块/选文）、目标语言、引擎模型与复用状态，可折叠；请求中与失败状态可见，失败不写入成功译文（事务式：翻译成功才落盘）。服务端调用 **MiniMax 中国站 MiniMax-M3.1-Flash**（OpenAI 兼容 `https://api.minimax.cn/v1/chat/completions`；国际站 api.minimax.io 不使用——密钥与模型订阅按站区分；密钥读环境变量 `MINIMAX_API_KEY`，仅服务端持有，客户端接口不含密钥字段）；译文按「文档 + 页解析身份（parseId）+ 来源（块 id 或归一化选文 sha256）+ 目标语言」键控存储与复用，**已有对应译文直接复用不重复翻译**；翻译完成自动持久保存，重开/重启恢复；**解析替换期间返回的旧翻译响应不写入新解析**（落盘前后双重校验 parseId）。未配置密钥时接口 503 + 界面明确提示，阅读不受影响。
- **双向联动**：原页叠加 bbox 覆盖层，与右侧内容块双向悬浮高亮；点击任一侧主动定位到另一侧对应区域；缩放后覆盖位置按当前渲染缩放重算；缺位置/无效位置的块照常展示，悬浮静默、主动定位失败给短提示不打断阅读。
- 阅读位置：变化后自动持久保存到服务，重启应用/服务后恢复上次阅读页与缩放。
- 独立服务：Readeva 服务为独立进程（Node），关闭浏览器不会终止服务；**Docling 解析服务**也是独立进程（Python，本机用 conda 环境 `readeva` 运行），地址可配置。

成果包导入导出等属于后续 Issue，不在当前范围。

## 环境要求

- Windows 10/11（首版在本机运行与测试）
- Node.js ≥ 20（在 v24 上验证）
- npm（随 Node 附带）

## 快速开始

```powershell
# 1. 安装依赖
npm install

# 2. 启动 Docling 解析服务（独立进程，需要 conda 环境 readeva）
conda run -n readeva python -m uvicorn docling_service.main:app --host 127.0.0.1 --port 5001
#   首次真实解析时 Docling 会自动下载模型到用户缓存目录。

# 3. 启动 Readeva 服务（另一个终端），并指向解析服务
npm start -- --docling-url http://127.0.0.1:5001
# 输出：
#   Readeva service listening on http://127.0.0.1:8787
#   Readeva data dir: <项目目录>\data
#   Readeva docling service: http://127.0.0.1:5001

# 4. 打开浏览器访问
#   http://127.0.0.1:8787
```

使用流程：点击「导入 PDF」（可多选）→ 书库列出文档 → 点「打开」进入阅读视图 → 原页立即渲染，当前页优先解析并按阅读顺序展示标题/段落/列表/表格/图片 → 后续页在后台按阅读位置优先补全，右侧内容列表顶部内联展示当前页解析状态（徽标/失败原因/重试按钮），面板头部一处静态文本显示整本进度 → 翻页后调度跟随新阅读位置重排未开始任务 → 失败页在内容列表中标红并展示原因，就地显式重试 → 关闭浏览器或重启服务后再次打开同一文档，阅读位置与**已完成页解析**均直接恢复（不重新解析）。关闭浏览器不会终止服务：运行中的页继续解析完成，宽限期（默认 5 分钟）后尚未开始的排队任务自动清除；重新打开文档取回已完成成果并按当前阅读位置重新调度未完成页。

## 配置

服务为独立进程，地址可按以下优先级配置（命令行参数 > 环境变量 > 默认值）：

| 配置 | 命令行 | 环境变量 | 默认值 |
| --- | --- | --- | --- |
| 监听端口 | `--port 9000` | `READEVA_PORT` | `8787` |
| 监听地址 | `--host 0.0.0.0` | `READEVA_HOST` | `127.0.0.1` |
| 数据目录 | `--data-dir D:\readeva-data` | `READEVA_DATA_DIR` | `<项目目录>\data` |
| Docling 解析服务地址 | `--docling-url http://127.0.0.1:5001` | `READEVA_DOCLING_URL` | （未配置时页解析不可用） |
| Docling 轮询间隔 | `--docling-poll-interval-ms 500` | `READEVA_DOCLING_POLL_INTERVAL_MS` | `500` |
| Docling 解析超时 | `--docling-timeout-ms 300000` | `READEVA_DOCLING_TIMEOUT_MS` | `300000` |
| 页解析并发上限 | `--parse-concurrency 2` | `READEVA_PARSE_CONCURRENCY` | `2`（与 docling_service 线程池并发对齐，最小 1；本机 2GB pagefile 建议不超过 2） |
| 背景扫全派发节流 | `--parse-sweep-delay-ms 0` | `READEVA_PARSE_SWEEP_DELAY_MS` | `0`（0 = 动态 pacing；设 >0 为固定间隔覆盖） |
| 动态 pacing 系数 | `--parse-sweep-pacing-factor 0.5` | `READEVA_PARSE_SWEEP_PACING_FACTOR` | `0.5`（间隔 = 最近 3 页平均转换耗时 × 系数，钳制 [0,5000]ms；**系数 0 = 关闭 pacing（不节流档）**；负数/非法值回落默认 0.5。pacing 状态按文档分桶：A 的间隔不挡 B；当前页豁免 pacing，不被背景间隔拖住） |
| 客户端会话宽限期 | `--client-grace-ms 300000` | `READEVA_CLIENT_GRACE_MS` | `300000`（5 分钟；毫秒；超过该时长无客户端活动即视为退出：完成已开始页、清除未开始队列。默认取 5 分钟是为**浏览器隐藏标签节流**留余量——隐藏标签页的页面内定时器被节流到约 1 次/分钟，阅读视图内 8s 慢刷新心跳被稀释后仍不会误判到期；需更短宽限期（如测试）可配置小值，但**必须大于客户端心跳间隔**；非法值/0 回落默认） |
| ECDICT 词典目录 | `--ecdict-dir D:\dict\ecdict` | `READEVA_ECDICT_DIR` | `<数据目录>\dict\ecdict`（目录内需有构建产物，见「词典数据准备」；未准备时查词返回明确提示，阅读不受影响） |
| MiniMax 翻译密钥 | （无命令行参数） | `MINIMAX_API_KEY` | （未设置时翻译不可用：接口 503 + 界面明确提示，阅读与查词不受影响；**指定环境变量，仅服务端读取，客户端不接触，接口不含密钥字段**） |
| MiniMax 接口地址 | `--minimax-url` | `READEVA_MINIMAX_BASE_URL` | `https://api.minimax.cn/v1`（**中国站/国内站官方文档的 OpenAI 兼容地址**；模型固定 `MiniMax-M3.1-Flash`。国际站为 `api.minimax.io`——密钥与模型订阅按站区分，**默认值必须是中国站**；此变量主要供测试指向 mock） |
| MiniMax 翻译超时 | `--minimax-timeout-ms 120000` | `READEVA_MINIMAX_TIMEOUT_MS` | `120000`（毫秒；M3.1-Flash 为思考型模型，长译文留足余量） |

解析服务地址与 MiniMax 密钥/地址都是**服务端配置**：客户端不接触解析服务地址与翻译密钥；未来解析服务部署到远端时仅需修改该地址，客户端与应用代码不变。未配置时阅读功能完整可用，右侧面板提示「解析服务未配置」。

## 词典数据准备（ECDICT，离线查词）

选词查词使用 [ECDICT](https://github.com/skywind3000/ECDICT)（MIT License）离线英汉词典。**词典数据下载与构建由 Hans 执行**（一次性：约 63MB 下载 + 本地构建）：

```powershell
# 1) 下载 ECDICT 词条 CSV（约 63MB，仓库 master 分支单文件，存入项目数据目录；data/ 已被 git 忽略）
curl.exe -L --create-dirs -o data\dict\src\ecdict.csv https://raw.githubusercontent.com/skywind3000/ECDICT/master/ecdict.csv

# 2) 构建本地查询数据（去重/排序/许可声明落盘，产出 3 个文件到默认词典目录）
node scripts\build-dictionary.mjs --csv data\dict\src\ecdict.csv

# 3) 重启 Readeva 服务后即可离线查词（服务默认从 <数据目录>\dict\ecdict 读取；
#    也可用 --ecdict-dir 指向其他目录）
```

构建产物（`ecdict.words.bin` 内存索引、`ecdict.entries.jsonl` 词条文件、`manifest.json` 来源/许可/统计）：查询时只读本地文件、**不访问网络**。manifest 内保留 ECDICT 的 MIT 许可声明与数据来源说明，查询接口随结果一并回传 `license`/`dataSources`，结果卡片页脚展示真实归因（manifest 缺少归因信息时降级为静态文案「释义来自本地 ECDICT 词典（MIT License）· 离线查询」）。未构建时查词给出明确提示（界面按 README 引导准备数据），阅读功能不受影响。

**产物体积与可删除重建**：构建产物约占 100–200MB 磁盘（词条文件 + 内存索引，来自约 63MB 的源 CSV 去重排序展开）；运行时索引常驻内存约 15MB。产物可随时删除重建：删除 `data/dict/ecdict/`（或整个 `data/dict/`）后，再跑一遍上面第 2 步的同一条构建命令即可恢复，不影响书库与解析数据。

构建前会校验下载到的文件：HTML/XML 错误页、Git LFS 指针、缺列/列数不符的表头、**词条数明显异常（低于下限，默认 1000，可用 `--min-entries N` 或环境变量 `READEVA_DICT_MIN_ENTRIES` 调整）**时构建直接失败并给出原因，不会产出空词典或残缺词典——避免把「下载到错误文件」静默构建成空词典。

浏览器端默认使用同源地址访问服务；如需指向其他地址（如未来部署在服务器上的服务），在书库页点「服务设置」填写服务基地址（保存在浏览器 localStorage）。

示例：

```powershell
npm start -- --port 9000 --data-dir D:\readeva-data
```

## 数据存储

```
data/
  documents.json              # 文档元数据（名称、页数、大小、内容身份、上次阅读）
  library/<sha256>.pdf        # PDF 副本（内容寻址，字节不变）
  progress/<sha256>.json      # 每份文档的阅读位置 { page, zoom, updatedAt }
  parses/<sha256>/page-N.json # 每页解析记录（解析身份、内容块、可用位置、元信息/失败原因）
  parses/<sha256>/index.json   # 每文档状态索引（状态字段 + 页文件 mtime/size 快照，冷启动免首轮逐页读全量）
  translations/<sha256>/<parseId>.json # 译文（按文档 + 页解析身份绑定：来源块 id 或归一化选文 sha256 + 目标语言）
  dict/src/ecdict.csv         # Hans 下载的 ECDICT 词条 CSV（构建输入，不参与运行时）
  dict/ecdict/                # 构建产物：内存索引 + 词条文件 + manifest（查词只读这 3 个文件）
```

- 文档身份 = 文件内容 SHA-256；把同一 PDF 改名后再导入不会产生新文档。
- 阅读位置在变化后立即写入磁盘（原子写入），服务重启、浏览器重启后均可恢复。
- 页解析完成后自动持久保存（成功与失败都落盘）；服务重启后已完成页直接取回，**不重新解析**；每文档状态索引 `parses/<sha256>/index.json` 在保存时增量更新，重启后冷启动经索引取状态（页文件被外部改动/删除时回退逐页读盘，正确性不依赖索引）。
- 翻译完成后自动持久保存（事务式：翻译成功才写入）；译文按「文档 + parseId + 来源 + 目标语言」键控，服务重启后直接取回，**不重新翻译**；页解析被替换（新 parseId）后旧译文不再出现在新解析的查询结果里。
- 客户端会话按文档跟踪（`lastSeen`）：阅读位置上报/进度轮询/状态轮询等任何文档活动都会刷新；超宽限期未活动的文档由服务自动完成运行中页并清除未开始队列，重连重新调度。
- 删除 `data/` 目录即可完全重置书库。

## 运行测试

浏览器端到端测试覆盖：导入多份 PDF → 相同内容不重复入库 → 再次打开并验证原页渲染 → 翻页/页码跳转/缩放 → 阅读位置自动保存 → **重启服务**并使用全新浏览器会话验证恢复；以及解析行为（全部使用固定 Docling 结果的 mock 服务，不依赖真实外部服务）：

- 服务级：解析请求/状态流转/结果获取、按阅读顺序的内容块、单页字节流上传校验、**重启后不重新解析**、已完成页复用、失败重试、参数校验；以及 Issue #5 的调度行为：阅读位置优先级、跳页重排、闲置补全整本、失败隔离、显式重试、显式请求插队、进度快照重启恢复、**pacing 按文档分桶**（A 的固定间隔不挡 B）、**当前页豁免 pacing**、**不节流档（系数 0）**；以及 Issue #6 的客户端会话行为：最后一次客户端请求后服务独立推进队列（浏览器关闭服务继续运行）、宽限期到期→运行中页完成+未开始任务清除（幂等）、宽限内回来队列不受影响、重连取回成果+按阅读位置重新调度、会话端点只读观察、**默认宽限期 300000ms**（隐藏标签节流取舍）、跨文档取任务轮转（round-robin，并发 1 严格交替 + 并发 2 反饥饿）、状态索引（index.json 落盘/重启读取/失效回退）。断言均基于 mock 记录的真实提交顺序。

## 架构简述

- `server/` —— 独立服务进程（Node/Express）：书库 API（导入、列表、文件、阅读位置）+ **页解析 API（请求/状态/结果、阅读页优先级更新、整本进度、客户端会话状态，Docling 服务适配层与调度器）** + **ECDICT 离线词典查询 API（`server/dictionary.js`：内存索引二分 + 词条文件切片，纯本地不访问网络）** + **翻译 API（`server/minimax.js` MiniMax 中国站适配层 + `server/translations.js` 译文存储：按文档+parseId+来源+目标语言键控，事务式保存与复用）** + 托管静态前端 + PDF.js 资源。接口契约不依赖客户端与服务共享文件路径（上传字节流、按 URL 取回文件、解析发送单页字节流）。
- `docling_service/` —— 独立 Docling 解析服务（Python/FastAPI，本机 conda 环境 `readeva`）：包装 docling 库，实现 docling-serve 兼容线协议（异步提交/状态轮询/结果获取），无状态，可被远端 docling-serve 或其他兼容服务替换。
- `web/` —— 浏览器应用（原生 ES Modules + PDF.js）：书库视图、阅读视图（原页 + 右侧解析面板 + bbox 覆盖层双向联动 + 面板头部整本进度静态文本（事件更新 + 阅读期间 8s 慢刷新） + 内容列表内联的单页状态 + **选词工具条与词典结果卡片（`web/dictionary.js`）** + **块翻译按钮与译文展示（`web/translator.js`）**）、阅读位置自动保存/恢复、解析状态与结构化内容展示。
- 后续任务（成果包导入导出等）将在同一服务进程内扩展端点。

详见 [docs/architecture.md](docs/architecture.md)。
